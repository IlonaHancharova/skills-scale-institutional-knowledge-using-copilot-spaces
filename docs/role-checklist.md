# Role Onboarding and Handoff Checklists

This document provides practical checklists for onboarding new team members and managing responsibility handoffs across all OctoAcme personas. Use these checklists to ensure smooth transitions, clear accountability, and reduced knowledge gaps.

---

## Developer Onboarding Checklist

### Day 1
- [ ] Access to repositories, code review tools, and CI/CD dashboards granted
- [ ] Development environment set up (IDE, dependencies, local build successful)
- [ ] Code of conduct and coding standards reviewed
- [ ] Introduction to team in daily standup

### Week 1
- [ ] Completed first code review (as reviewer or author)
- [ ] Read and understand Definition of Done
- [ ] Reviewed testing guidelines and coverage expectations
- [ ] Paired with experienced developer on small task
- [ ] Access to deployment environments (staging, production read-only)

### Month 1
- [ ] Delivered first feature end-to-end (design, code, tests, deployed)
- [ ] Participated in sprint planning and estimation
- [ ] Familiar with incident response and rollback procedures
- [ ] Completed security and compliance training

### Handoff Activities
- [ ] Document current work in progress with clear status
- [ ] Transfer ownership of open PRs (reassign or complete)
- [ ] Update technical documentation for areas of ownership
- [ ] Conduct knowledge transfer session with successor
- [ ] Archive or update relevant design documents

## Cross-Role Handoff Best Practices

### For All Handoffs
1. **Schedule dedicated handoff time** (minimum 2 hours, more for complex roles)
2. **Document everything** - Don't rely on verbal communication alone
3. **Create a handoff document** listing:
   - Current work in progress with status
   - Key contacts and relationships
   - Critical deadlines and commitments
   - Known risks and issues
   - Access and permissions needed
   - Important context and history
4. **Provide shadow time** - Allow incoming person to observe before taking over
5. **Maintain availability** - Be available for questions for at least 2 weeks post-handoff
6. **Use team channels** - Announce handoffs publicly to ensure everyone knows who to contact

### Communication Template for Role Handoff

**Subject:** [Role] Handoff - [Outgoing Person] to [Incoming Person]

**Key Information:**
- Effective Date: [Date]
- Handoff Meeting: [Date/Time]
- Shadow Period: [Start] to [End]

**Current Responsibilities:**
- [List active projects, tasks, or areas of ownership]

**Critical Contacts:**
- [Name, Role, Context for relationship]

**Upcoming Deadlines/Commitments:**
- [Date, Deliverable, Stakeholder]

**Known Risks/Issues:**
- [Risk/Issue, Impact, Current mitigation]

**Access Needed:**
- [System/Tool, Permission Level, How to request]

**Questions?** Contact [Outgoing Person] via [preferred channel]

## Using These Checklists

- **New team members**: Work through the relevant onboarding checklist with your manager/mentor
- **Managers**: Use these to structure onboarding plans and track progress
- **Role transitions**: Reference handoff sections when someone is leaving or changing roles
- **Process improvement**: Update these checklists based on retrospective feedback and lessons learned

These checklists are living documents - contribute improvements through the standard PR process.
